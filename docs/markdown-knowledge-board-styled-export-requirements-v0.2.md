## 1. 目的

Markdown Knowledge Boardで作成・保存したノートを、文章の内容に合ったデザインのHTML文書として書き出す。受け取った人はKnowledge Boardを使わず、一般的なブラウザで閲覧できる。同じデザインでPDF用の印刷も行えるようにする。

配布用デザインとして、**標準のカラー21種類、デザイン8種類、および文字サイズの定型倍率**を独立して選択できるようにする。選んだ組み合わせを単一HTMLとデザイン付きPDFに反映する。

## 2. 前提・対象範囲

- 入力の中心は、Knowledge Boardで編集中または保存済みの**選択中の1ノート**とする。既存のMarkdown取り込み、Edit、Preview、Save、Markdown書き出しを利用する。
- 文章の編集機能は新設しない。本文Markdownとノートのタイトル・タグは既存画面で編集する。
- 新設するのは、配布用デザインの編集、完成形のプレビュー、単一HTMLのダウンロード、同じデザインでのPDF印刷である。
- 既存の **Print / PDF** は、従来のPreviewに基づく手軽な印刷として残す。新機能の設定は既存Print / PDFの出力に影響させない。
- 本機能はブラウザ内で処理する。HTML/PDFの作成を目的にノート本文をサーバーへ送信しない。既存のオフライン利用中も機能する。

## 3. 画面と操作

### 3.1 メニュー

選択中ノートの **More actions** メニューを次のようにする。表記は既存画面に合わせて英語とする。

| 表示順 | 項目 | 挙動 |
| --- | --- | --- |
| 1 | Metadata | 既存どおり |
| 2 | Export Markdown | 現在の **Export** の名称を明確化する。書き出す `.md` の内容と動作は変えない |
| 3 | Print / PDF | 既存どおりの簡易印刷。配布用デザインを適用しない |
| 4 | Export Styled HTML / PDF… | 新しい配布用出力画面を開く |
| 区切り線の下 | Delete | 既存どおり |

- 新しい項目は、保存済みノートおよび編集中の新規ドラフトで利用できる。ノートがない場合は既存メニューの無効状態に従う。
- PCとモバイルのメニューで項目名・アイコンが欠けたり重なったりしない。

### 3.2 配布用出力画面

- 初期表示時に現在の**タイトル、タグ、本文、配布用デザイン設定**から完成プレビューを生成する。未保存の本文変更も反映する。
- **Color／Design／Text size** の選択を独立したコントロールとして配置する。変更は完成プレビューへ即時反映し、画面用とPDF用の見た目を確認できるようにする。
- 主な操作は **Apply to note**、**Download HTML**、**Print / PDF**、**Cancel／Close** とする。Apply to noteはデザイン設定だけをノートの編集状態に反映し、本文を変更しない。ノートへの永続化は既存のSaveで行う。
- Download HTMLとPrint / PDFは**画面内の一時的な選択**を使って出力する。Apply to noteを押していなくても出力できる。出力操作だけではノートのデザイン設定・本文・未保存状態を変更しない。
- 出力画面はHTMLダウンロードの開始後、印刷ダイアログから戻った後も開いたままとする。選択した設定を維持し、続けて調整・再出力できる。ブラウザがダウンロード先への保存またはPDF保存を完了したかどうかは判定しない。
- Apply to note後も画面を開いたままとする。次の表で、一時的な選択、ノートの編集状態、保存済みノートの扱いを定義する。

  | 操作・結果 | 画面内の一時的な選択 | ノートの編集状態 | 保存済みノート |
  | --- | --- | --- | --- |
  | Colorなどを選び直す | 更新し、プレビューに反映 | 変えない | 変えない |
  | Apply to note | 現在の選択を維持 | 選択を反映。保存済み内容と異なれば未保存状態にする | Saveまで変えない |
  | Download HTMLを押し、ファイル生成・ダウンロード開始 | 維持し、画面も維持 | 変えない | 変えない |
  | HTMLの生成・事前検査が失敗 | 維持し、理由を表示 | 変えない | 変えない |
  | ブラウザ側でダウンロードを取り消す | 維持する。取り消し結果は検知しない | 変えない | 変えない |
  | Print / PDFを押し、ブラウザ印刷画面へ進む | 維持し、戻っても画面を維持 | 変えない | 変えない |
  | 印刷の準備失敗／印刷ダイアログでキャンセル | 維持し、必要なら理由を表示 | 変えない | 変えない |
  | Apply前のCancel／Apply後のClose | 最後のApply以降の一時的な変更だけ破棄し、画面を閉じる | Apply済みの設定や既存の本文変更は維持 | 変えない |
  | ノート画面でSave | ― | 本文・タイトル・タグ・Apply済みデザインをまとめて保存 | 更新する |

- Apply済みで一時的な選択だけがさらに変わっている場合、閉じる操作は **Close（未適用の変更を破棄）** と示す。Applyで確定した変更はCloseでは戻さず、既存のRevertまたは未保存確認のDiscardで戻す。
- 本文の未保存変更のみ、デザインの未保存変更のみ、両方ある場合のいずれも**同じノートの未保存状態**として扱う。別ノート選択、削除、再読込、PWA更新など既存の未保存確認が出る操作では、既存の **Save／Discard／Cancel** を使い、Saveは両方保存、Discardは両方破棄、Cancelは移動を中止する。出力画面内だけの一時的な変更はノートの未保存判定に含めない。
- 出力が失敗した場合は、理由と再試行方法を表示する。出力画面を開いている間に背後のノートが切り替わらないようにし、開始時のノートと出力時のノートを一致させる。

## 4. デザイン要件

### 4.1 初期提供する設定

- **標準カラーテーマ21種類**をすべて選べる。既定は**スレート**とする。対象は次のとおり。

  | 分類 | 選択肢 |
  | --- | --- |
  | ベーシック（6） | スレート／オーシャン／フォレスト／プラム／アンバー／フレッシュライム |
  | モノトーン（2） | モノクロ／グラファイト |
  | 淡色・くすみ（7） | セージ／サンド／サクラ／パウダーブルー／ミント／ラベンダー／アプリコット |
  | 高級・ダーク（4） | ミッドナイト／ボルドー／ナイト／ノワール＆ゴールド |
  | 黒基調＋差し色（2） | オニキス ミント／オニキス レッド |

- **標準デザインテーマ8種類**をすべて選べる。既定は**コンフォート**とする。

  | 選択肢 | 体裁の特徴 |
  | --- | --- |
  | コンフォート | ゆったりした標準デザイン |
  | コンパクト | 情報密度を高めたレイアウト |
  | エディトリアル | 雑誌風の誌面 |
  | フォーマル | かっちりした文書 |
  | ソフト | 大きめの角丸を使ったやわらかい印象 |
  | テクニカル | 帯見出しを使った技術文書 |
  | 帳票 | 罫線主体の帳票 |
  | Webサイト | Web向けに上下の余白と見出しの差を強調 |

- **ColorとDesignは互いに独立**して選択でき、全21×8の組み合わせを使用できる。どちらかを切り替えても、他方の選択とText sizeは維持する。
- カラーの内部値は次の固定IDとし、右欄の色を**配布用HTML・印刷の主アクセント色の初期仕様値**とする。本文色・背景色・リンク色などの従属色は、各配色に合わせてコントラストを確保し、同じIDなら常に同じ値になるようテーマ定義に固定する。ここに挙げる色値は本拡張の実装仕様であり、外部アプリケーションとのピクセル単位の再現性は要求しない。

  | 表示名 | 保存値 | 主アクセント色 | 区別する外観 |
  | --- | --- | --- | --- |
  | スレート | `slate` | `#475569` | 青みのある灰色 |
  | オーシャン | `ocean` | `#0369A1` | 深い青 |
  | フォレスト | `forest` | `#15803D` | 深い緑 |
  | プラム | `plum` | `#7E22CE` | 紫 |
  | アンバー | `amber` | `#B45309` | 黄褐色 |
  | フレッシュライム | `fresh-lime` | `#4D7C0F` | 黄緑 |
  | モノクロ | `monochrome` | `#171717` | 黒と白 |
  | グラファイト | `graphite` | `#404040` | 濃淡のある灰色 |
  | セージ | `sage` | `#557C65` | くすんだ緑 |
  | サンド | `sand` | `#92734D` | くすんだ黄土色 |
  | サクラ | `sakura` | `#B54B75` | 淡い桃色の背景と濃い桃色の文字 |
  | パウダーブルー | `powder-blue` | `#39779E` | 淡い水色の背景と青色の文字 |
  | ミント | `mint` | `#187F70` | 淡い緑の背景と深緑の文字 |
  | ラベンダー | `lavender` | `#7757A8` | 淡い紫の背景と紫の文字 |

- Designの保存値・外観の違いは次のとおり。各行の余白・罫線・見出しなどは同じColorに対しても切り替わり、Color側はレイアウトを変えない。

  | 表示名 | 保存値 | 見出しと本文 | 表・区切り・余白 |
  | --- | --- | --- | --- |
  | コンフォート | `comfort` | 中程度の見出し、標準的な行間 | 余白を広めにとり、薄い横罫 |
  | コンパクト | `compact` | 見出し間隔と行間を小さくする | 表のセル余白を小さくする |
  | エディトリアル | `editorial` | 大きい第1見出し、本文との強い大小差 | 章間に広い余白、細い区切り |
  | フォーマル | `formal` | 抑制した見出し、整った階層 | 直線的な罫線、均等な余白 |
  | ソフト | `soft` | やわらかい背景面を使う見出し | 引用・コードに角丸の枠 |
  | テクニカル | `technical` | 帯状の見出し、コードを明確に区別 | 表の見出し行を強調、項目間隔を揃える |
  | 帳票 | `form` | 小さめの見出し、情報を揃える | 表と区切りに明確な罫線、詰めた余白 |
  | Webサイト | `website` | ページ冒頭と節見出しに大きい差 | 画面では広めの左右余白、表は横スクロール可 |
- **文字サイズの定型倍率**として、**80%、85%、90%、95%、100%（既定）、105%、110%、115%、120%、130%、150%**の11種類を、この順で選べる。デザインテーマの文字サイズを基準に、本文・見出し・表・コードなどの文字サイズを同じ比率で変更する。倍率はColor／Designを変更しても維持する。**pxで指定**と任意の倍率入力は設けない。
- 21色と8デザインは、**名称だけでなく各選択肢の視覚的特徴**（配色、見出し、余白、枠、表など）を設計する。Markdown Knowledge Boardが出力する要素に適用し、Markdownに存在しない独自の文書パーツは増やさない。
- **「カスタム」系は初期範囲外**とする。任意のアクセント色・書体・本文幅・行間・pxでの文字サイズ入力、カスタムカラー／カスタムデザインの作成・編集、「マイテーマ」「マイデザイン」の登録は設けない。書体・余白・行間などは選んだDesignの定義に従う。
- タイトル、見出し、段落、リスト、チェックリスト、リンク、引用、表、コード、画像、Mermaid図、区切り線に一貫したスタイルを適用する。
- 配布文書のタグ表示は任意とし、**初期値は非表示**にする。Knowledge Board固有のID・更新日時・操作ボタンなどは含めない。
- ページ先頭のタイトルが本文先頭の同名の第1見出しと重なる場合は、配布文書で同じタイトルを二重に表示しない。異なる場合は双方を残す。
- HTMLは狭い画面でも読みやすく表示し、幅の広い表・コード・図は内容を欠落させず閲覧できるようにする。
- ナイト／ノワール＆ゴールドなど暗い配色をPDF印刷する場合は、背景色を自動的に明るい別テーマへ変えない。印刷プレビューに暗い背景を反映し、インク使用量が増えることを分かるようにする。

### 4.2 設定の保存

- 配布用デザイン設定（Color、Design、Text size、タグ表示の有無）は**各ノートが所有する**。アプリ共通の配布用デザイン設定は持たない。ノートを再度開いたとき、最後にSaveした選択を復元する。新規ノートと設定を持たない既存ノートはスレート／コンフォート／100%／タグ非表示から始める。
- 設定項目には既定値とバージョンを持たせ、以前のノートやバックアップを開いた場合は既定デザインを適用する。
- 既存のJSONバックアップ／復元、および対象ノートを扱うクラウドバックアップ／復元で設定が失われないようにする。古いバックアップの復元も妨げない。
- 既存の `.md` 書き出しにはデザイン設定を混ぜない。`.md` だけを再取り込みした場合は本文を復元し、配布用デザインは既定値から始める。

## 5. 出力要件

### 5.1 共通の出力内容

- HTMLとデザイン付きPDFは、操作時点の**同じノートのスナップショット**（未保存変更を含む）と同じデザイン設定を使用する。
- 変換する構文と未対応時の動作を次に固定する。原文のMarkdownを自動書換えしない。

  | 入力 | 配布用出力での扱い |
  | --- | --- |
  | 見出し1～6、段落、改行、太字・斜体、引用、番号付き／箇条書き／入れ子、区切り線 | 意味を保ったHTML要素へ変換 |
  | インライン／フェンス付きコード、言語指定 | コードとして表示。対応言語は既存Previewのハイライト規則に従い、未知の言語はプレーンなコード |
  | GFMの表・取り消し線・自動リンク・脚注・チェックリスト | 表示する。チェックボックスは配布文書では操作不可、脚注から本文へ往復できる |
  | `==ハイライト==` | 既存Previewと同様に強調表示 |
  | Markdown画像、代替テキスト | §5.2の方法で画像を埋め込み、代替テキストを保持 |
  | `mermaid` コードブロック | SVGを文書内に静的表示。描画失敗時は元のコードと理由を表示し、警告付きで続行できる |
  | 文書内の `#見出し` リンク | HTML内の見出しへ移動。重複見出しには一意のIDを付ける |
  | 生のHTMLタグ | 文字として表示し、タグとして解釈・実行しない。検出した箇所を事前検査に通知 |
  | 数式記法 `$…$`／`$$…$$`、その他の非対応拡張記法 | 元の文字列を表示し、数式描画は行わない。`$$` のブロックは事前検査に通知 |

- ノートにあるメタデータの構文は本文に二重出力せず、タイトルとタグの扱いは§5.2に従う。空の本文でもタイトルのみの文書を出力できる。
- リンクを次のように処理する。事前検査の一覧はリンク本文、元URL、ノート内の行番号と理由を示す。通知対象が複数ある場合は一括表示する。

  | リンク種別 | 出力結果・対応 |
  | --- | --- |
  | `#見出し`、脚注 | 配布文書内のIDへ変換。対象がなければ警告し、利用者の **Continue without local links** によりリンクを外した本文として出力、またはCancelで戻る |
  | `https:`／`http:`／`mailto:` | 通常の外部リンクとして残す。HTMLの表示自体には接続不要。印刷ではURLを脚注などに自動付加しない |
  | `別ノート.md`／`.markdown`、相対ファイル、ルート相対パス | 別ノートの内容は含めない。警告して **Continue without local links** を選ぶと、リンクを外した本文として出力。Cancelで戻る |
  | `javascript:`／`data:` などリンク先として危険な方式 | 移動先を削除し、本文だけを出力。事前検査で理由を表示 |

- 問題の一覧表示、画像の解決、リンクの続行確認はHTMLとPDF印刷の**共通の事前検査**で行う。未解決の画像がある場合は両方の出力を開始しない。リンクだけに問題がある場合は明示的な続行を許し、続行の選択もノート本文や設定へ保存しない。

### 5.2 HTMLダウンロード

- UTF-8の `.html` を**1ファイル**としてダウンロードする。CSSおよび必要な画像・図のデータをファイル内に含め、表示のための外部JavaScript、CSS、CDN、Knowledge Boardへの通信を必要としない。
- HTMLファイルを対象ブラウザで直接開いた場合に閲覧できる。本文は画像化せず、文字選択・検索・コピーができる。スクリプトは含めず、インラインCSSと埋め込み画像／SVGだけで完成する。
- 保存名はノートタイトルの前後空白を除き、制御文字と `\\ / : * ? " < > |` を `_` に置換し、末尾の空白・ピリオドを除いた先頭80文字に `.html` を付ける。結果が空なら `Untitled.html` とする。タイトル文字列は文書の `<title>` と文頭の表題にエスケープして載せる。本文先頭の第1見出しが前後空白を除いてタイトルと一致する場合は表題と重複表示しない。
- タグは設定がONのときだけ表題の下に文字として表示し、HTMLのメタタグやファイル名には入れない。ID、更新日時、編集UIは出力しない。PDFの表題・タグ表示も同じ規則とする。
- 画像の参照を次のように解決し、正しい画像データとMIMEを確認してHTML内に埋め込む。元のMarkdown本文やノートの保存内容には画像の置換結果を反映しない。

  | 画像の参照 | 解決方法 |
  | --- | --- |
  | `data:image/png`、`jpeg`、`gif`、`webp` | データを検査してそのまま埋め込む。壊れたデータはエラー |
  | SVG画像、Mermaidの描画結果 | スクリプト・外部参照を含まない安全な静的SVGのみ埋め込む。検査に失敗した画像はエラー |
  | `https:` の画像 | ブラウザから匿名取得でき、CORSで読み取り可能な画像だけ埋め込む。認証、通信失敗、CORS拒否時はエラー。既存Previewに見えるだけでは取得可能とみなさない |
  | 相対／ルート相対パス、`file:`、`blob:`、取得不能なURL | 参照ごとにローカルの画像ファイルを選び、プレビュー・出力用に対応づける。対応づけ不能ならエラー。同名ファイルが複数ある場合も参照文字列とノート内の位置で区別する |

- 対応する画像形式はPNG、JPEG、GIF、WebP、安全な静的SVG。画像1点の展開後サイズは10 MiB、合計30 MiBまで。超過、形式不一致、解決不能のときは**ノート内の行番号、元の参照、理由、画像を選び直す操作**を示し、HTMLダウンロードとPDF印刷を開始しない。画像は配布HTMLに外部URLを残さない。画像ファイルの選び直しは出力画面内に限る。
- ダウンロードしたHTMLを開き直して編集する機能は初期範囲に含めない。編集の正本はKnowledge Boardのノートである。

### 5.3 デザイン付きPDF

- 新しい画面の **Print / PDF** は、HTMLと同じデザインの印刷用表示をブラウザの印刷ダイアログに渡す。PDFの保存先と確定操作はブラウザ／OSが担当する。
- 初期値はA4縦、上下16 mm・左右14 mmの余白とする。見出しと直後の本文1段落を可能な範囲で同じページに置き、表が改ページをまたぐときはヘッダー行を再表示する。1ページより長い表・コードは分割し、長い行は折り返し、図は紙幅に縮小して欠落させない。印刷色はブラウザの「背景のグラフィックを印刷」に依存するため、無効でも文字・罫線で読めるようにする。
- 印刷画面にはKnowledge Boardのナビゲーション、編集UI、出力ダイアログを含めない。色を印刷しない設定の環境でも読めるようにする。
- ブラウザの印刷ダイアログをキャンセルしてもノート本文と既存の **Print / PDF** の動作を変えない。

## 6. 品質・互換性

- オフラインのPWAでノートとデザインの編集、プレビュー、HTMLダウンロード、PDF印刷の呼び出しを行える。Web画像を取得する必要がある場合は、オフラインで解決できないことを明示する。
- 出力HTMLを開いた環境ではアプリの認証、クラウド機能、Service Workerを必要としない。
- 確認対象はWindows 11の現行安定版Chrome／Edge／Firefox、macOSの現行Safariとする。スマートフォン表示は現行iOS Safariで確認する。PCでは保存したHTMLを `file://` で直接開き、スマートフォンでは同一HTMLを静的HTTPS配信して確認する。保存したHTMLの閲覧時は通信を切り、開発者ツールまたはネットワークログで外部資産の読み込みがないことを確かめる。
- アプリ側のオフライン確認は、PWAを事前にインストールし、ノートを保存してから通信を切ってアプリを再起動した状態で行う。PDFそのものの保存はブラウザ／OSに委ねる。
- 見出し階層、画像の代替テキスト、リンクの識別性、キーボード操作、フォーカス表示、文字と背景のコントラストを確保する。
- 長文、画像・図を含む文書では進行状況を示し、ブラウザが固まったと誤認させない。描画待ちに上限を設け、失敗箇所を明示する。
- Markdown本文やファイル名からHTMLを生成する際、文字・属性・URLを適切に処理する。利用者が書いたスクリプトが配布HTMLで動作しないようにする。

## 7. 受入条件

1. **回帰**：Export Markdownの `.md` と既存Print / PDFの動作・出力を変更しない。出力画面では保存済み本文と未保存本文をそれぞれプレビュー・HTML・印刷に反映する。新規ドラフトでも同じ操作ができる。
2. **設定と遷移**：未保存本文だけ、Apply済みデザインだけ、両方、出力画面内の未適用選択だけの4状態を作る。各状態でDownload HTML、印刷ダイアログへの移動、HTML生成失敗、印刷キャンセル、Close、別ノートへの切替を実行し、§3.2の表と同じ状態になる。未適用選択だけではノートの未保存確認が出ない。Apply済みの場合はSave／Discard／Cancelで本文とデザインを一体として処理する。ダウンロードを始めた時点を成功とし、ブラウザ内での保存完了を推測しない。
3. **永続化**：ノートAとBで異なるColor／Design／Text size／タグ表示をSaveし、再起動後に各ノートの設定を復元する。JSONおよびクラウドのバックアップ／復元後も復元し、設定のない旧バックアップと `.md` 再取り込みでは既定値となる。
4. **選択肢**：§4.1の21色・8デザイン・11倍率が表記と保存値どおりに選べ、既定がスレート／コンフォート／100%である。全21×8組み合わせと全11倍率で変更・再読込・HTML生成がエラーにならず、他のコントロールの値が維持される。px入力やCustomは表示しない。
5. **外観の詳細確認**：次の8組を各1ページ以上のプレビュー、単一HTML、印刷プレビューで照合する。共通の試験ノートには日本語、見出し1～6、段落、引用、リスト、表、チェックリスト、取り消し線、脚注、ハイライト、コード、画像、Mermaid図、同一文書内リンクを含める。各組で§4.1のアクセント色とDesign固有の見出し・余白・罫線が現れ、80～150%の倍率が指定どおり文字へ反映される。

   | Color | Design | Text size |
   | --- | --- | --- |
   | スレート | コンフォート | 100% |
   | モノクロ | コンパクト | 80% |
   | オーシャン | エディトリアル | 105% |
   | ボルドー | フォーマル | 110% |
   | サクラ | ソフト | 95% |
   | オニキス ミント | テクニカル | 120% |
   | アンバー | 帳票 | 130% |
   | ナイト | Webサイト | 150% |

6. **構文と安全性**：§5.1の全行を入力して期待したHTML要素または文字列が得られる。重複見出しのリンク、脚注往復、描画できないMermaidのコード表示、生HTML・`<script>`・数式記法の文字表示、危険なURLの無効化を確認する。空本文でもタイトルのみを出力する。
7. **画像とリンク**：`data:` 画像、匿名取得可能なHTTPS画像、対応づけた相対パス画像をHTMLへ埋め込み、オフライン閲覧時に欠けない。取得不能・認証が必要・CORS拒否・壊れたデータ・SVGの危険な内容・容量超過は元参照と行番号を示してHTML／PDFの開始を止める。別ノートと存在しないアンカーは利用者がContinue without local linksを押した場合に限り、リンクなしの文字で出力する。Cancelでは本文と保存状態が変わらない。
8. **ファイルとメタデータ**：タイトル `企画: A/B?` の出力名が `企画_ A_B_.html` になり、タグは初期状態で非表示、ONにした場合だけ表示する。本文冒頭にタイトルと同名のH1があれば二重表示しない。IDや更新日時、編集UIを含めない。
9. **独立したHTML**：Windowsの対象3ブラウザとmacOS Safariで保存したファイルを直接開き、通信を切った状態でも画像・図・文字選択・検索・文書内リンクが機能する。現行iOS Safariでは静的HTTPS配信した同一ファイルを通信を切る前に取得し、表示中に資産への追加通信なしで閲覧できる。外部CSS・JavaScript・フォント・画像の要求が0件である。
10. **印刷**：冒頭と末尾に固有の確認文字列を入れた3ページ以上のA4縦文書で、両文字列がPDFに各1回現れる。ページ末近くの見出し、2ページにまたがる表、紙幅を超えるコード行、幅広いMermaid図を含め、見出しだけの孤立ページや内容の左右・上下の欠落がない。表見出しを各ページで確認し、背景の印刷をOFFにしても本文・表の区別ができる。印刷をキャンセルしてもノート状態が変わらない。
11. **オフライン**：§6の事前準備後にPWAをオフラインで再起動し、外部参照を含まない保存済みノートからHTMLダウンロードと印刷ダイアログ呼び出しを完了できる。外部画像を含むノートでは理由と画像の選び直しを表示する。

## 8. 初期範囲外

- カスタムテーマ、ユーザー作成テーマの登録、Markdownにない文書パーツの追加。標準21色・8デザイン・文字の定型倍率は**初期範囲に含む**。
- プレビュー上で文章を直接書き換える編集機能。
- 複数ノートの一括HTML出力、ノート間リンクを維持したWebサイト生成。
- HTMLを書き戻してKnowledge Boardのノートへ変換する機能。
- サーバーに文書を公開する機能、URL発行、共同編集。
- ブラウザの印刷ダイアログを介さないPDFの直接ダウンロード。
- 生HTMLの実行、数式の組版、別ノートや相対ファイルをまとめたサイトの生成。

## 9. 実装時の分割方針

1. 配布用デザイン設定と完成プレビューを、既存Edit・Previewの振る舞いから独立させて追加する。
2. HTMLとデザイン付きPDFで本文変換・デザイン定義を共有し、両者の差分を印刷用CSSに限定する。
3. 画像・Mermaid・リンクの解決と出力前の問題検出を、HTML保存／PDF印刷の直前に共通で行う。
4. 既存Markdown書き出し、既存Print / PDF、ノート保存、バックアップ／復元の回帰を確認する。

この文書は追加機能の要求範囲と受入条件を定める。カラーの従属色、各Designの詳細な寸法、画面レイアウトは、ここで固定した選択肢・アクセント色・差異・状態遷移を満たす形で詳細設計時に確定する。
