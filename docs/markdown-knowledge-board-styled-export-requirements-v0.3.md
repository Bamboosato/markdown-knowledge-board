# Markdown Knowledge Board 配布用 Styled Export 要件定義書 v0.3

- 作成日: 2026-09-28
- 状態: 実装反映版
- 更新日: 2026-10-06（印刷のタイトル・ページ番号仕様を追記）
- 更新元: `markdown-knowledge-board-styled-export-requirements-v0.2.md`

## 1. 目的

選択中の1ノートから、配布用デザインを設定してプレビューし、単一HTMLとしてダウンロード、または同じデザインで印刷／PDF保存できる機能を追加する。既存のMarkdown書き出しと簡易印刷は維持する。

### 1.1 基本方針

- 配布用デザイン設定は出力画面内だけの一時設定とする。ノート、IndexedDB、JSON／クラウドバックアップへ保存しない。
- 出力画面を閉じたら、画面内の設定、画像の対応付け、警告への続行選択を破棄する。次回は既定値から開始する。
- HTMLとPDF印刷は同じ本文変換、画像・リンク事前検査、デザイン定義を使い、差分は印刷用CSSに限定する。
- 本文、タイトル、タグは既存のノート状態を読む。未保存の本文変更も現在のプレビューと出力に反映する。
- 文書作成処理でノート本文をサーバーへ送信しない。出力機能はブラウザー内で動作する。

### 1.2 初期範囲外

- ノートへのデザイン設定保存、Apply／Revert、設定のバックアップ・復元。
- 複数ノートの一括出力、ノート間リンクを維持するWebサイト生成。
- プレビュー内での本文編集、サーバー公開、URL共有、直接PDFダウンロード。
- 生HTMLの実行、数式の組版、カスタムテーマ作成。

## 2. 入口と画面

### 2.1 ノートメニュー

| 表示順 | 項目 | 挙動 |
| --- | --- | --- |
| 1 | Metadata | 既存どおり |
| 2 | Export Markdown | 既存のExportの名称を明確化する。`.md`の内容と動作は変更しない |
| 3 | Print / PDF | 既存どおりの簡易印刷。配布用デザインを適用しない |
| 4 | Export Styled HTML / PDF… | 新しい配布用出力画面を開く |
| 区切り線の下 | Delete | 既存どおり |

### 2.2 出力画面

- ダイアログではなく、既存のEdit／Preview／Slidesと同じメイン領域へ画面遷移して表示する。既存タブ行はタイトル `Export Styled HTML / PDF`、`Print / PDF`、`Download HTML`、右端の閉じるアイコンに置き換える。閉じるアイコンは `Back to Preview` として操作でき、出力画面の枠は通常のPreview／Editパネルと同じ位置・幅・高さに揃える。
- 出力画面の外枠は通常Previewと同じ角丸とし、内側のスクロール領域は角丸なしで表示する。スクロールバーと文書ページの間に余白を設け、文書ページには画面プレビューとダウンロードHTMLの両方でDesignに応じた角丸を適用する。
- `Back to Preview`で通常のPreviewへ戻り、出力画面内の一時設定を破棄する。背後の編集領域は保持し、編集中の本文・選択状態を失わない。
- 開いた時点の選択中ノートのタイトル、タグ、本文から完成プレビューを作る。未保存の本文変更も反映する。
- Color、Design、Text size、タグ表示を独立した一時設定として表示し、変更をプレビューへ即時反映する。
- 操作は `Download HTML`、`Print / PDF`、`Back to Preview` とする。出力の違いを画面に説明する。
- 画面を開いている間に対象ノートが切り替わらないようにする。出力には画面を開いた時点の同一ノートのスナップショットを使う。
- HTMLダウンロード開始後および印刷ダイアログから戻った後も画面を開いたままにし、設定を維持して再調整・再出力できる。
- `Back to Preview`で画面内の一時設定を破棄する。本文、ノートの保存状態、既存の未保存確認には影響させない。
- 出力操作だけでは本文、ノートの保存状態、未保存状態を変更しない。ブラウザーが保存先への書き込みやPDF保存を完了したかは判定しない。
- 出力が失敗した場合は、理由と再試行方法を表示する。

## 3. 一時設定

### 3.1 既定値

- Color: スレート
- Design: コンフォート
- Text size: 100%
- タグ表示: OFF

これらは出力画面を開くたびに適用し、ノートデータには書き込まない。

### 3.2 Color（21種類）

| 分類 | 選択肢 |
| --- | --- |
| ベーシック（6） | スレート／オーシャン／フォレスト／プラム／アンバー／フレッシュライム |
| モノトーン（2） | モノクロ／グラファイト |
| 淡色・くすみ（7） | セージ／サンド／サクラ／パウダーブルー／ミント／ラベンダー／アプリコット |
| 高級・ダーク（4） | ミッドナイト／ボルドー／ナイト／ノワール＆ゴールド |
| 黒基調＋差し色（2） | オニキス ミント／オニキス レッド |

### 3.3 Design（8種類）

| 表示名 | 保存値 | 表示上の特徴 |
| --- | --- | --- |
| コンフォート | `comfort` | 中程度の見出し、標準的な行間、広めの余白、薄い横罫 |
| コンパクト | `compact` | 小さい見出し間隔・行間・表セル余白 |
| エディトリアル | `editorial` | 大きな第1見出し、章間の広い余白、細い区切り |
| フォーマル | `formal` | 抑制した見出し、整った階層、直線的な罫線 |
| ソフト | `soft` | 柔らかい背景面、引用・コードの角丸枠 |
| テクニカル | `technical` | 帯状の見出し、コードと表見出しを明確に区別 |
| 帳票 | `form` | 小さめの見出し、情報を揃えた表と明確な罫線 |
| Webサイト | `website` | ページ冒頭と節見出しに強弱、画面では広めの左右余白 |

### 3.4 Text size

80%、85%、90%、95%、100%、105%、110%、115%、120%、130%、150%の11種類をこの順に選べる。100%を既定値とし、px指定や任意倍率入力は設けない。選択したDesignの文字サイズを基準に、本文、見出し、表、コードなどの文字サイズへ同じ比率を適用する。Color／Designの変更では倍率を変えない。

### 3.5 タグ表示

タグ表示は任意で、既定値はOFFとする。ONの場合はノートのタグを配布文書に表示する。

## 4. 文書内容とMarkdown変換

- 配布文書にはH1のタイトル、本文、選択された場合のタグを含める。ID、更新日時、編集UI、Knowledge Boardの操作要素は含めない。
- Markdown本文直下に空でないH1見出しがある場合、最初のH1の文字列を配布文書上部のH1に使い、元の位置では重複表示しない。2つ目以降のH1は本文内に残す。H1がない場合はノートのメタ情報の`title`を配布文書のH1に使う。コードブロックや引用内の見出しは文書タイトルの候補にしない。
- HTMLの`<title>`とダウンロードファイル名には、本文のH1と異なる場合もノートのメタ情報の`title`を使う。文書タイトルに使った見出しのIDは維持し、文書内リンクの参照先を失わない。
- 対応対象は見出し、段落、箇条書き、番号付きリスト、チェックリスト、リンク、引用、表、コード、画像、Mermaid、区切り線、脚注、取り消し線、ハイライト。
- 見出しIDと脚注参照は文書内リンクに変換する。重複見出しでも一意に移動できるようにする。
- 描画できないMermaidは元のコードを表示する。
- 生HTMLは実行せず、文字列として表示する。数式記法は組版せず、入力された文字列を表示する。
- 未対応構文や安全に変換できない内容を黙って欠落させず、出力前に理由と場所を示す。

## 5. 画像・リンクの解決

HTMLダウンロードとPDF印刷の直前に同じ事前検査を行う。エラー箇所には可能な範囲で元参照と行番号を示す。

### 5.1 画像

| 画像参照 | 解決方法 |
| --- | --- |
| `data:image/png`、JPEG、GIF、WebP | データを検査して埋め込む。破損・容量超過はエラー |
| SVG、Mermaid描画結果 | スクリプト・外部参照を含まない安全な静的SVGだけを埋め込む。検査に失敗したらエラー |
| HTTPS画像 | 匿名取得を試み、CORSで読み取り可能な画像だけを埋め込む |
| 相対／ルート相対パス、`file:`、`blob:`、取得不能URL | 利用者がローカル画像ファイルを選び、参照ごとに対応付ける |

- 外部HTTPS画像の取得前に、外部サーバーへ接続することを画面で説明する。認証付き取得はしない。
- HTTPS画像の取得タイムアウトは15秒とする。画像1件の最大サイズは5 MiB、出力に含める全画像の合計上限は20 MiBとする。上限を超えた場合は対象画像と上限値を表示し、出力を開始しない。
- 取得状況、失敗理由、タイムアウトを表示する。通信失敗、CORS拒否、認証必須、破損データ、危険なSVG、容量超過の場合はローカル画像選択を案内する。
- ローカル画像は参照ごとに選択でき、同名ファイルも個別に対応付けできる。必要な画像が未解決の場合は出力を開始しない。
- 対応付けは出力画面内だけで保持し、`Back to Preview`時に破棄する。取得・選択した画像をアプリ内には保存しない。
- 出力HTMLには画像データを埋め込み、オフライン閲覧時に外部画像通信を必要としない。

### 5.2 リンク

| リンク種別 | 出力結果・対応 |
| --- | --- |
| `#見出し`、脚注 | 文書内の対応IDへ変換。対象がない場合は警告する |
| `https:`／`http:`／`mailto:` | 外部リンクとして保持。表示に接続を必要としない。印刷時にURLを自動追記しない |
| 別ノート、相対ファイル、ルート相対パス | 出力文書にリンク先を含めない。該当箇所を示し、利用者が `Continue without local links` を選んだ場合だけリンク先を外して出力する |
| `javascript:`、`data:`など危険な方式 | 出力前に方式と箇所を通知し、移動先を削除して本文だけを出力する |

リンクだけに問題がある場合は、`Continue without local links` を明示的に選ぶと出力できる。未選択のまま `Back to Preview` で閉じれば出力しない。警告への選択はノートや次回の画面に保存しない。

## 6. HTML出力

- 外部CSS、JavaScript、フォント、画像への依存がない単一HTMLをダウンロードする。
- CSSはHTML内に含め、Mermaidは静的な安全な図として埋め込む。実行時にスクリプトや追加通信を必要としない。
- ファイル名はタイトルを基に生成し、Windowsで使えない `: / \\ ? % * | " < >` 等を `_` に置き換える。空タイトルは `note.html` とする。
- 保存後に対象アプリへログインしていない環境でも開ける。表示、文字選択、ページ内検索、文書内リンクを利用できる。
- 画面幅が狭い場合も読みやすくし、幅の広い表・コード・図を横スクロール等で内容を欠落させず閲覧可能にする。

## 7. 印刷／PDF

- 新しい `Print / PDF` はHTMLと同一デザインを印刷用表示に渡す。PDF保存先と確定操作はブラウザー／OSが担当する。
- 初期値はA4縦。見出し直後の改ページを抑え、表見出しを可能な範囲で繰り返し、図やコードの欠落を防ぐ。
- 長い表・コードは必要に応じてページをまたいで分割し、本文を省略しない。紙幅を超えるコード行や幅広い図は縮小または分割する。
- Knowledge Boardのナビゲーション、編集UI、出力画面のコントロールを印刷しない。
- 色を印刷しない設定でも本文・罫線・表の区別を判読できるようにする。暗い配色を自動で別テーマに置き換えず、背景色を含む印刷プレビューを反映し、インク使用量が増える旨を表示する。
- 印刷ダイアログをキャンセルしてもノート状態は変わらず、出力画面へ戻る。
- CSS page margin box対応ブラウザでは、上中央にsnapshotのmetadata title（空なら`Untitled`）、右下に`page / pages`を表示する。本文H1から選ぶ文書内見出しとは区別する。HTMLからの印刷とアプリからの直接印刷で同じ規則を使用する。非対応ブラウザでは余白欄の表示を保証しない。

## 8. 対象環境・オフライン

- 初期検証対象は、Windowsの現行Chrome／Edge、macOS Safari、iOS Safari、Android Chromeとする。検証時に実際のブラウザー名・バージョンを記録する。
- レイアウト確認幅はデスクトップ1280px、スマートフォン390pxを基準とする。
- 独立HTMLはWindowsの対象ブラウザーとmacOS Safariでローカルファイルとして開き、ネットワークを切って閲覧する。
- iOS Safariでは同一HTMLを静的HTTPS配信から取得した後、ネットワークを切って表示を確認する。追加の資産通信なしで閲覧できること。
- PWA自体のオフライン確認では、事前にアプリをキャッシュした後、オフラインで再起動する。外部参照のない保存済みノートからHTMLダウンロードと印刷ダイアログの呼び出しができること。
- オフライン中に解決できない画像参照がある場合は、該当箇所とローカル画像選択方法を示す。

## 9. 受け入れ条件・テスト観点

### 9.1 観点

- **機能・状態遷移**：保存済み本文／未保存本文、新規ドラフト、出力成功・失敗・中止、画面を閉じた後の初期化。
- **データ**：空本文、長文、タイトルとタグ、全対応Markdown、画像・リンク参照、特殊文字を含むファイル名。
- **UI・印刷**：4種類の一時設定、即時プレビュー反映、画面と印刷の整合、ページ境界、色なし印刷。
- **非機能・環境**：対象ブラウザー、画面幅、オフライン、単一HTMLの追加通信なし、危険な入力の非実行。

### 9.2 受け入れ条件

1. **回帰**：Export Markdownの`.md`内容、および既存Print / PDFの動作・出力が変更されない。配布用設定は両方へ影響しない。
2. **入力状態**：保存済み本文、未保存本文、新規ドラフトそれぞれからプレビュー、HTML、印刷を利用できる。出力画面を開く前後、出力後、Previewへ戻った後でノート内容・未保存状態が変わらない。
3. **一時設定**：Color／Design／Text size／タグ表示を個別に変更するとプレビューへ即時反映し、HTMLと印刷にも反映される。Previewへ戻った後に再度開くと既定値へ戻る。
4. **表示選択肢**：21色、8デザイン、11倍率をすべて選択できる。倍率はpx入力なしで変更でき、Color／Design変更後も保持される。
5. **構文と安全性**：§4の構文を確認する。重複見出しの移動、脚注往復、描画不能Mermaidのコード表示、生HTML・`<script>`・数式記法の文字表示、危険URLの無効化を確認する。空本文ではタイトルだけを出力する。
6. **画像**：data画像、匿名取得可能なHTTPS画像、対応付けたローカル画像をHTMLへ埋め込み、オフライン閲覧で欠けない。取得不能、認証必須、CORS拒否、タイムアウト、破損データ、危険SVG、容量超過、未対応付けでは原因と場所を示し、画像が欠けた文書の出力を開始しない。
7. **リンク**：別ノート・存在しないアンカーは、明示的に続行した場合だけリンクを外して出力する。未選択のまま画面を閉じれば出力しない。危険URLは通知して移動先を削除する。
8. **ファイルとメタデータ**：メタ情報のタイトル`企画: A/B?`のファイル名が`企画_ A_B_.html`となる。タグは既定で非表示、ON時だけ表示する。本文直下の最初の空でないH1を文書上部に一度だけ表示し、メタ情報のタイトルと異なる場合もH1を増やさない。H1がない場合はメタ情報のタイトルを表示する。2つ目以降のH1と最初のH1への文書内リンクを維持し、ID・更新日時・編集UIは含めない。
9. **独立HTML**：対象デスクトップブラウザーでローカルファイルとして開き、通信切断後も画像・図・文字選択・検索・文書内リンクが機能する。外部CSS／JavaScript／フォント／画像への要求がない。
10. **印刷**：冒頭と末尾に固有の確認文字列がある3ページ以上のA4文書を印刷し、両方が各1回含まれる。ページ末近くの見出し、2ページにまたがる表、紙幅を超えるコード行、幅広いMermaid図を含め、見出しだけの孤立ページや内容の上下左右の欠落がない。背景印刷OFFでも読め、キャンセル後もノート状態が変わらない。
11. **オフライン**：§8の事前準備後、PWAをオフラインで再起動し、外部参照のない保存済みノートからHTMLダウンロードと印刷ダイアログ呼び出しを完了できる。未解決画像は理由と選択方法を示す。
12. **失敗時**：出力失敗で画面内の一時設定を保持し、理由と再試行方法を表示する。HTMLダウンロード開始や印刷ダイアログを閉じただけで、保存成功を誤って通知しない。

### 9.3 実施範囲

実装時のテストは、変更範囲とリスクに応じて対象ケース、クロスブラウザー、または全件から選ぶ。実施範囲、選定理由、未実施範囲、ブラウザーとバージョンを結果に記録する。
