# MKB Phase 2 — 配布用文書出力 追加要件定義書 v0.1

- 作成日: 2026-11-05
- 状態: レビュー用・未承認
- 対象: `Bamboosato/markdown-knowledge-board`
- 関連: [Styled Export要件 v0.3](./markdown-knowledge-board-styled-export-requirements-v0.3.md)、[Styled Export詳細設計](./markdown-knowledge-board-styled-export-design.md)、[Phase 1要件](./pdf-print-quality-phase1-requirements-v0.1.md)

## 1. 目的と基本方針

単一ノートのStyled HTML/PDF出力を対象に、文書レイアウト設定、表紙、**ページ番号なしの目次**を追加し、配布文書の完成度を高める。既存の簡易 `Print / PDF`、Markdown編集・Preview・Slides・保存・バックアップ・PWAは維持する。pfpdfの組版思想は参考にするが、Phase 2ではpfpdf/Vivliostyle/Paged.jsを新規導入しない。

## 2. スコープと優先度

| ID | 要件 | 優先度 | Phase 2 |
| --- | --- | --- | --- |
| PDF-06 | 用紙・向き・余白の文書レイアウト設定 | Must | 対象 |
| PDF-07 | 表紙とページ番号なしの目次の自動生成 | Must | 対象 |
| PDF-09 | 本文ページ番号、ヘッダー、フッター | Should | 技術検証・実装可否判断 |
| PDF-08 | 複数ノートの選択・結合出力 | 保留 | Phase 3以降 |

**対象外:** ページ番号付き目次、複数ノート結合、ノート間リンク統合、直接PDFダウンロード、カスタムテーマ編集、数式組版、表紙へのロゴ・著者等の追加入力、設定の永続化。

## 3. 既存仕様の維持

- Styled Exportを開いた時点の単一ノート `{title, tags, body}` の固定snapshotを使い、未保存変更を反映する。
- 21 Color、8 Design、11段階Text size、Show tagsを維持。既存既定値はslate/comfort/100%/タグOFF。
- 新しい設定も画面内だけの一時stateとし、閉じると破棄する。Note型、IndexedDB、JSON/クラウドバックアップ、dirty状態は変更しない。
- HTML/印刷は既存の安全なReact/AST描画経路と資産検査を共有。raw HTMLの実行、危険URL、未検証SVG、未解決画像の出力禁止を緩和しない。
- 単一HTMLに外部CSS、script、font、画像への依存を残さない。出力操作を保存成功と誤認して通知しない。

## 4. PDF-06 文書レイアウト設定

| 項目 | 選択肢 | 既定値 | 適用先 |
| --- | --- | --- | --- |
| Paper size | A4 / Letter | A4 | 印刷 |
| Orientation | Portrait / Landscape | Portrait | 印刷 |
| Margin | Standard / Narrow / Wide | Standard | 印刷 |
| Cover page | Off / On | Off | HTML・印刷 |
| Table of contents | Off / On | Off | HTML・印刷 |
| TOC depth | H2 / H2–H3 | H2–H3 | HTML・印刷 |

- 既存のColor/Design/Text size/Show tagsとは独立した「Document layout」設定群とする。具体的な余白mm値は詳細設計時に定め、用紙サイズ・向きごとに検証する。
- 用紙・向き・余白は印刷用CSSに適用。ブラウザ/OSの印刷ダイアログによる上書きがあり得ることを画面に明示する。単一HTMLの画面閲覧幅は用紙設定で不必要に制限しない。
- 390px幅では設定を折りたたみ可能とし、操作部がプレビューを圧迫しないようにする。キーボード操作、ラベル、フォーカス移動に対応。
- Cover/TOCをOffとしたときの従来出力を回帰保証する。

## 5. PDF-07 表紙

- Cover page=Onで文書冒頭に表紙を1回だけ生成。印刷では表紙の後に改ページする。
- 表紙タイトルは既存Styled Exportのタイトル規則を再利用する（本文直下の最初の空でないH1、なければsnapshot.title）。元のH1は本文側に重複表示しない。既存見出しIDとアンカーを維持する。
- Show tags=Onの場合のみ表紙へタグを表示する。表紙なしのタグ表示位置は既存仕様を維持する。
- 空タイトル、長い日本語タイトル、特殊文字を安全に表示する。
- 副題、著者、日付、ロゴ、表紙テンプレート編集は対象外。

## 6. PDF-07 目次（ページ番号なし）

- TOC=Onで本文Markdownの見出しから目次を自動生成する。対象はH2、H3。H1は文書タイトルとして扱い、目次には含めない。
- TOC depth=H2はH2のみ、H2–H3は両方を階層表示する。見出し順は本文順に従い、見出し本文のテキストを目次ラベルに使用する。
- 見出しIDは既存の重複回避規則を再利用し、脚注IDと衝突させない。HTMLでは目次項目から見出しへ遷移できる。PDFでは目次を静的なテキスト階層として表示し、**ページ番号を表示しない**。
- 配置順は、表紙Onなら「表紙→目次→本文」、表紙Offなら「目次→本文」。印刷では目次後に改ページする。長い目次が複数ページにまたがっても欠落させない。
- 対象見出しが0件の場合、空の目次を出力せず、その理由を設定画面に表示する。本文は通常どおり出力する。
- 目次は元Markdown本文を変更しない。表示は安全なReactコンポーネントで構築し、HTML文字列の直接連結で生HTMLを挿入しない。
- ページ番号付き目次と、目次から本文ページへの厳密なページ参照はPhase 3以降の検討事項。

## 7. PDF-09 ページ番号・ヘッダー・フッター（技術検証）

- CSS Paged Mediaとブラウザ標準印刷の対応状況を検証する。候補設定はPage number/Header/FooterをそれぞれOff既定とする。
- ブラウザ標準のヘッダー・フッターとの二重表示、表紙のページ番号除外、ページ総数表示の可否を確認する。
- 正確な表示を保証できない環境では推測値を出さず、非対応の案内または機能無効化とする。PoCの結果により実装をPhase 3以降に延期できる。
- **PDF-09の採否はPDF-06/07のMust要件の完了を妨げない。**

## 8. 出力処理と状態

1. Styled Exportを開き、対象ノートのsnapshotを固定。
2. Markdown ASTを解析し、見出しID・脚注IDを確定。
3. 一時設定から表紙/目次の表示モデルを生成。
4. 既存の画像・リンク・Mermaidの検査・解決を行う。
5. 同一の安全な文書DOMを画面プレビュー、単一HTML、印刷に利用。
6. 画面終了で一時設定・解決済み資産を破棄する。

Styledのsnapshotはノート選択変更だけでは失効しない。画面終了/unmount・新出力セッションで旧処理を失効させる。Phase 1で定義した初期化/印刷準備timeout・失敗表示・再試行を維持する。

## 9. 非機能要件

- **セキュリティ・プライバシー:** 新たな本文外部送信なし。既存の画像5 MiB/件、合計20 MiB、HTTPS取得15秒、SVG・URL検査を維持。
- **オフライン:** PWA資産が準備済みで外部資産に依存しないノートなら、表紙・目次付きHTMLの生成と印刷呼出しが通信なしでできる。
- **検証環境:** Windows Chrome/Edgeの自動検証、Android Chrome実機確認を中心とする。Safari/iPhoneは必須ゲート外とし未検証事項に記録する。
- **操作性:** 1280px、390px、キーボード、アクセシブル名、フォーカス復帰を確認。
- **性能:** 表紙・目次Offの従来出力に顕著な退行がない。定量閾値は実装前ベースラインを取得して決める。

## 11. 実装計画案

- PR-A: PDF-06の設定UI、用紙/向き/余白CSS、回帰テスト。
- PR-B: PDF-07の表紙モデル、タイトル処理、HTML/印刷。
- PR-C: PDF-07の目次抽出、階層、アンカー、長い目次の印刷。
- PR-D: PDF-09の技術PoCと採否記録（実装は別途判断）。

各PRは既存CI、unit/E2E、セキュリティ監査結果と未実施範囲を明記する。ユーザー承認なしにmergeしない。

## 12. 詳細設計時の確認事項

1. Standard/Narrow/Wideの具体的な余白mm値。
2. 表紙・目次の印刷時改ページとHTML表示時の区切り表現。
3. 見出し中のインライン装飾・リンクを目次ラベルへ変換する規則。
4. 用紙設定のブラウザ別対応・上書き時の表示。
5. PDF-09のPoC合格条件とPhase 3への延期基準。

本書は既存Styled Export要件 v0.3とPhase 1要件を置換せず、Phase 2の追加仕様として適用する。
